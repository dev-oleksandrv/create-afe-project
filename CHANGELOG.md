# Changelog

All notable changes to the template are listed here, newest first. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[`docs/maintaining.md`](docs/maintaining.md), section 4.

## [Unreleased]

The template moves from Copier to the npm package `create-afe-project` (ADR 0002, proposed), on
the owner's instruction of 2026-10-31; no observed failure, the aim is to drop the Python
toolchain for users. It is the first release on npm, as 1.0.0, under the MIT license
(`LICENSE`).

### Added

- `npx create-afe-project@latest <directory>` (or `npm create afe-project@latest`) creates a
  project with a wizard that asks the questions of the former `copier.yml`; `--defaults`,
  `--data key=value`, and `--data-file` answer without a terminal.
- `npx create-afe-project@latest update` updates a project: it replaces the template-owned files,
  keeps the project block of `AGENTS.md`, creates missing seeded files and never changes existing
  ones, removes files the template no longer owns, runs the migrations between the versions, and
  regenerates the generated files. It refuses a dirty working tree (`--allow-dirty`) and a
  downgrade, and lists every replaced local edit of a template-owned file.

### Changed

- The answers file is `.afe-answers.json` with the template version in `_version`; a project
  generated by Copier converts its `.copier-answers.yml` on its first update. The path classes
  (`scripts/lib/classes.sh`), the protect hook, and the size warning of
  `scripts/check-decisions.sh` know both names.
- `docs/contributing.md`, section 5, `docs/documentation-rules.md`, section 9, `README.md`
  (seeded: copy its "Project template" section by hand), and the `update-template` skill describe
  the update with `create-afe-project` instead of `copier update`; there are no conflict markers
  to resolve any more.
- Template repository: `copier.yml` becomes `src/config.js`, `template/.gitignore` becomes
  `template/_gitignore` (npm never publishes a `.gitignore`), `scripts/sync-self.sh` runs the
  `update` command, the tests run the CLI (`scripts/checks.d/05-cli.sh`,
  `scripts/checks.d/10-template.sh`), and the `release` workflow also publishes to npm.

### Removed

- Copier: `copier.yml`, the template of `.copier-answers.yml`, and the `--trust` requirement.

## [0.6.0] - 2026-10-31

A second pass over the Agent-Friendly Engineering field guide, on the owner's decisions of
2026-10-31, and the follow-ups of 0.5.0. Observed failures: the protect hook let two writes into
rule files through, behind `cd` and in a Python heredoc (pull request #14); the review workflows
skipped #14 and reported success. The other additions come from the owner's decisions on the
guide, without an observed failure.

### Added

- Environment contract: `scripts/env.sh setup|check|fast|e2e|reset` runs the project's commands
  `SETUP`, `CHECK_FAST` (default `scripts/check-docs.sh`), `E2E`, and `RESET` of
  `.claude/harness.conf`, and `scripts/check.sh` for `check`; an unset command is SKIP, and the
  exit code is the command's. `AGENTS.md`, section 2, and the map point at it.
- `fail_without_change` module: `.github/workflows/fail-without-change.yml` runs
  `scripts/env.sh setup` and the driver on every pull request; the label `tests-pass-on-base`
  allows a pass. The driver installs with `SETUP` when `FWC_INSTALL` is empty, and a test must
  now also pass with the change, so a missing toolchain is no longer evidence.
- Access control: `.claude/settings.json` denies reading `.env`, `.env.*`, `*.pem`, and `*.key`
  (also through `cat` and the like); a project that needs one, such as `.env.example`, takes the
  rule out with `"remove": {"permissions": {"deny": ["Read(**/.env.*)"]}}` in
  `.claude/settings.project.json`, which `scripts/gen-settings.sh` now supports.
- Metrics: the measure "Regression of" (`none` or `#N`), required by readiness;
  `scripts/pr-metrics.sh` adds the regression rate, the hours to merge, and the median and
  maximum of each measure.
- A small diff: readiness warns, without failing, above `DIFF_WARN_LINES` (default 400) changed
  lines, generated files left out.
- `contracts/*` is class high by default in `.claude/path-classes`.

### Changed

- Review before the pull request runs without the `dual_review` module too: one pass by a fresh
  Claude subagent, which `create-pr` runs, for classes normal, gate, and high; the module adds
  the Codex CLI and the Santa loop. `review-code` always checks that "Checks" names it.
- `.claude/hooks/protect-docs.sh`: a target behind `cd DIR` or `git -C DIR` resolves against
  that directory; the file names in an interpreter's heredoc are targets; the body of another
  heredoc is not read as commands.
- `docs/contributing.md`: section 1, a session that stops unfinished leaves a checkpoint
  (commits pushed, progress and blockers in the plan or the description), and GitHub deletes
  merged branches; section 5, shorter; section 6, a defect fix gives the evidence pack.
- `docs/documentation-rules.md`, section 2: acceptance criteria as Given, When, Then with their
  checks; architecture holds the system map with domain ownership and dependency rules.
  `docs/testing-rules.md`: the project names the levels of its verification ladder.

### Seeded files: what an existing project does by hand

- `.claude/harness.conf`: add `SETUP=`, `CHECK_FAST=scripts/check-docs.sh` (or the project's
  fast check), `E2E=`, `RESET=`, and `DIFF_WARN_LINES=400`.
- `.claude/path-classes`: add `high contracts/*` when the project has contracts.
- `docs/README.md`: the row "Environment commands" names `scripts/env.sh`; the planned rows of
  architecture and operations name the system map, domain ownership, and dependency rules, and
  logs, traces, metrics, and scenario replay.
- On GitHub, turn on "Automatically delete head branches" in the repository settings.

## [0.5.0] - 2026-10-31

The process follows the Agent-Friendly Engineering principles: the owner sets outcomes and
risks, agents report evidence, checks enforce, and governance follows risk and reversibility.
Recurring failure addressed: in `xandronak/brain`, pull requests #14, #15, and #18 each needed
three or more AI review rounds that never converged, because every round found new edge cases;
and each owner decision needed a separate confirmation. Additions without an observed failure,
from the owner's decisions on the AFE field guide (2026-10-30): the invariants register, the
environment commands, access control for irreversible actions, and the size budget. Open pull
requests of an existing project need the new description sections before readiness passes.

### Added

- Path classes (`docs/documentation-rules.md`, section 8): low, normal, gate, high, approval, by
  built-in rules and the new seeded `.claude/path-classes` (`<class> <glob>` lines), with
  defaults for several ecosystems. Each class decides approval before the edit (approval: the
  protect hook asks), the listing in the pull request (gate: "Gate files"), and the review
  before it (none, one reviewer, or the Santa loop for high). `scripts/lib/classes.sh` and
  `scripts/check-decisions.sh --classes` print the class of each changed path and the review it
  needs. `AGENTS.md`, section 4, follows the classes.
- Loops (`docs/contributing.md`, sections 3 and 6): the Ralph loop on `scripts/check.sh` for
  every change, capped by `RALPH_MAX_ITERATIONS` (default 5) in the new seeded
  `.claude/harness.conf`; the Santa loop for class high only, with a Claude subagent and the
  Codex CLI until neither finds a blocker, and after the third round the open blockers go to the
  owner. Other classes get one pass; only the fix of a blocker is checked again.
- Definition of done in `docs/contributing.md`, section 3, which `AGENTS.md`, section 6, points
  at; it replaces the definition-of-done line of `docs/documentation-rules.md`, section 6.
- Modules `acceptance_check` (`scripts/check-acceptance.sh`: every identifier of the Acceptance
  section appears in a test file of `TEST_GLOBS`; run by readiness) and `fail_without_change`
  (`scripts/fail-without-change.sh`: each new or changed test fails on the base, in a temporary
  worktree, with the project's own `FWC_INSTALL` and `FWC_TEST`, an optional `FWC_CLASSIFIER`,
  and `--allow-pass-on-base` for the label `tests-pass-on-base`). Both off by default.
- `scripts/check-decisions.sh --ready` also fails on: no "Acceptance and test plan"; an
  Acceptance item that is neither "None" with a reason nor names an existing path in backticks;
  an added `Decided by the owner, YYYY-MM-DD` marker in a Markdown file that "Owner decisions"
  does not name; a touched gate file that "Gate files" does not name; Metrics tables outside
  their forms, answers that do not add up, a blocker recorded as a limit, or a missing measure.
- `scripts/pr-metrics.sh`: sums the Metrics tables of merged pull requests with `gh`, names the
  sensors without a finding, and warns when `--limit` cuts the period. `docs/maintaining.md`,
  section 6 (this repository): at each release a rule or check that never fired is proposed for
  removal, and a new one names the recurring failure it addresses.
- Access control: `.claude/settings.json` is now generated by `scripts/gen-settings.sh` from the
  template-owned `.claude/settings.template.json` and the new seeded
  `.claude/settings.project.json`, where the project adds its own permission rules; the template
  denies force pushes and remote branch deletions in the forms its rules spell out.
  `scripts/check-template.sh` fails on a stale `.claude/settings.json`.
- `.claude/hooks/protect-docs.sh`: asks for class approval paths (`approval` lines of
  `.claude/path-classes`, `.claude/settings.project.json`, `.mcp.json`, the generated settings),
  and for the irreversible commands it names: `git push` that forces, deletes, mirrors, prunes,
  or pushes tags (`--tags`, `refs/tags/...`, `v<digit>...`), `gh pr merge`, `gh release create`
  and `delete`, `gh repo delete`.
- Line budgets checked by `scripts/check-template.sh`: `AGENTS.md` 90 template lines,
  `docs/documentation-rules.md` 200, `docs/contributing.md` 200, `docs/testing-rules.md` 80. The
  four rule documents together are shorter than in 0.4.1.
- The invariants register `docs/invariants.md` as a planned document kind; its invariants are
  criteria of the Santa loop. Environment commands in the map, pointed at from `AGENTS.md`. One
  git worktree per parallel session (`docs/contributing.md`, section 1).

### Changed

- `docs/contributing.md`, section 3: description sections Summary, Acceptance and test plan,
  Checks, Assumptions and open questions, Owner decisions, Gate files, Metrics (two fixed
  tables), Notes for the owner. The new label `limit:` records a suggestion the branch does not
  fix. A failing check keeps its command and output. The owner's merge confirms the listed
  markers; readiness waits for no confirming comment and no second round.
- `docs/contributing.md`, section 6: AI review is a sensor; classes `blocker` and `suggestion`;
  each finding is answered once; a suggestion never drives a loop. The `docs-review` and
  `code-review` workflows run once, when a pull request opens or leaves draft; a push or a reopen
  does not run them again.
- `docs/testing-rules.md`: the agent derives the test plan from the identifiers, as a report; a
  refactoring keeps the tests; a behaviour change changes the requirement first, then the test
  with the same identifier; gate configurations are class gate; the threat model of development
  gates only decides which bypass is a blocker.
- Skills: `dual-review` reviews by class; `create-pr` runs the Ralph loop, writes the new
  sections, waits for the review runs once, and has a fixed blocker checked once by a fresh
  subagent; `review-code` and `docs-review` use the two classes and no longer judge whether a
  marker matches the owner's words.

### Removed

- The `should`/`nit` classes and their example table, the brief rule for later rounds, the
  escalation after three rounds outside the Santa loop, "Owner decisions to confirm" and its
  confirming comment, the template-update exemption of 0.4.1 (now class low), and the checklist
  of `docs/contributing.md`, section 4, which is now one paragraph.
- `.claude/protected-paths` is no longer seeded; the hook and the class checks still read its
  glob lines as class approval.

### Seeded files: what an existing project does by hand

- An update creates `.claude/path-classes`, `.claude/harness.conf`, and
  `.claude/settings.project.json` with the defaults, and deletes `.claude/protected-paths`; a
  `_migrations` entry of `copier.yml` appends its glob lines to `.claude/path-classes` as
  `approval <glob>`. Check them by hand: gate configuration, such as test runner and linter
  files, becomes `gate <glob>`. Add the project's own high paths
  (brain: policy, limits, accounting). Set `TEST_GLOBS`, `FWC_TEST`, and `FWC_INSTALL` in
  `.claude/harness.conf` before turning on the new modules (`copier update --data
  acceptance_check=true --data fail_without_change=true`).
- `.claude/settings.json` becomes generated: a project that edited it moves its own rules into
  `.claude/settings.project.json` and runs `scripts/gen-settings.sh`.
- `docs/README.md`: add the row "Environment commands: set up, check, fast check, end-to-end
  tests, reset" (check: `scripts/check.sh`; the others the project's commands or "not
  decided"), the planned row "Invariants" (`docs/invariants.md`), and in the rows of the agent
  rules, the documentation rules, and checks and enforcement the new terms: autonomy by risk,
  when a change is done, path classes and access, `.claude/path-classes`,
  `.claude/harness.conf`, `.claude/settings.project.json`, `scripts/pr-metrics.sh`.

## [0.4.0] - 2026-10-30

### Changed

- `docs/testing-rules.md`, section 4: a threat model of development gates. Gates catch honest
  mistakes and shortcuts; deliberate evasion is left to the review of the diff; product
  invariants are not development gates. The protected-paths bullet now names the forms the
  protect hook catches and what is left to the review, instead of claiming that no agent loosens
  a gate.
- `docs/documentation-rules.md`, section 7: the merge-readiness row names what
  `scripts/check-decisions.sh --ready` checks and what is left to the owner.
- `docs/contributing.md`, section 6: a finding that only deliberate evasion can exploit to bypass
  a development gate is a `nit`, a bypass of a product invariant keeps its severity, and a table
  of `should` and `nit` examples calibrates every reviewer. The Tests criterion includes the test
  plan. With `dual_review`, later rounds add the owner's decisions on the branch to the brief, and
  nothing else.
- `docs/contributing.md`, section 1: "one logical change" means one mechanism with its tests and
  owner documents, with examples.
- `docs/contributing.md`, section 3: the description gains the sections "Test plan" (always,
  written before the implementation) and "Owner decisions to confirm" (each `Decided by the
  owner` marker added on a chat instruction, confirmed by the owner with one comment); a pull
  request is ready to merge only after that confirmation. `scripts/check-decisions.sh --ready`
  does not check the confirmation.
- `docs/documentation-rules.md`, sections 3 and 7: a statement about a check names the forms it
  catches and what is left to the review; an absolute claim needs a test for each form it covers.
- `create-pr` skill: writes the two new sections and reports unconfirmed owner decisions as
  waiting on the owner. `review-code` skill: compares the code and tests with the test plan.
  `dual-review` skill: an author's self-check before the first round, the severity examples and
  the test plan in the brief, and the owner's decisions from the second round.

### Fixed

- `.claude/hooks/protect-docs.sh`: judges a target path by the git repository that holds it when
  that repository has `.template/owned.txt`, so an edit in a sibling git worktree, or in another
  generated project, asks the owner like an edit in the session's own checkout. Other paths
  inside the session's project are judged by the project as before (no git yet, a nested
  repository); paths elsewhere stay unguarded. A relative path of a shell command resolves
  against the hook input's `cwd`.
- `.claude/hooks/protect-docs.sh`: folds `.` and `..` in the part of a target path that does not
  exist yet before the match, so a write to `newdir/../AGENTS.md` or `docs/new/../README.md` asks
  the owner, and a path whose `..` leaves the repository no longer matches a protected glob.

## [0.3.1] - 2026-10-30

### Changed

- `docs/contributing.md`, section 6: defines the severities `blocker`, `should`, and `nit`, and
  that a review fails on a `blocker` or `should` only; a reviewer who hesitates picks `nit`. The
  `review-code`, `docs-review`, and `dual-review` skills apply these definitions, and a `nit` no
  longer fails a round of the dual review.
- `review-code` and `docs-review` skills: in a pull request run they read changed files of
  `.claude/`, `CLAUDE.md`, and `.mcp.json` from the diff and `.claude-pr/`, because
  `anthropics/claude-code-action` restores those paths from the base branch.

## [0.3.0] - 2026-10-30

### Added

- Testing rules (`docs/testing-rules.md`), template-owned: what a test is for, how it proves
  behaviour, tests and the change they cover, and the gates no agent loosens. `AGENTS.md`,
  section 2, points to it; `docs/documentation-rules.md`, sections 2, 6, and 7, list it.
- Review of pull requests (`docs/contributing.md`, section 6): a rubric that every reviewer
  applies, the project's own criteria in an owner document that the map names under "Review
  criteria", and the rule that a defect found after the merge names what keeps the next one out.
- Module `code_review` (question `code_review`, default on): the `code-review` workflow
  (`.github/workflows/code-review.yml`) and the `review-code` skill
  (`.claude/skills/review-code/SKILL.md`) review pull requests that change code, contracts,
  checks, or workflows against that rubric with Claude Code, with the same secret and app as
  `docs-review`, and install no plugin.
- Module `dual_review` (question `dual_review`, default off): the `dual-review` skill
  (`.claude/skills/dual-review/SKILL.md`) reviews a branch before its pull request with a Claude
  subagent and the Codex CLI in a read-only sandbox, after a passing `scripts/check.sh`, for at
  most three rounds, without commits; its verdict goes under "Checks" in the description
  (`docs/contributing.md`, sections 3 and 4).

### Changed

- `create-pr` skill: waits for and answers the `code-review` run next to `docs-review`, and with
  the `dual_review` module runs the dual review when the branch has no verdict for its tree.
- `docs/contributing.md`, section 3: every review comment is answered before the merge, from
  either review workflow.
- Linter configuration (`.markdownlint-cli2.jsonc`): in `CHANGELOG.md`, headings need to be
  unique among siblings only, so that each version can have its own Added and Changed.
- Seeded `docs/README.md`: rows for the testing rules and the review of pull requests, and the
  planned "Review criteria" section. An existing project copies these rows by hand.

## [0.2.0] - 2026-10-29

### Changed

- `create-pr` skill (`.claude/skills/create-pr/SKILL.md`), with the `docs_review` module: after
  opening the pull request it waits for the `docs-review` run, answers every comment (a fix in
  its own commit, a decline with a reason, or a question for the owner), records the outcome in
  the description, and reports it; a draft or a run that does not finish is reported instead of
  waited for. `docs/contributing.md`, section 4, names the new step.

## [0.1.0] - 2026-10-29

### Added

- Agent rules (`AGENTS.md` with one project block, `CLAUDE.md`), documentation rules with file
  ownership (`docs/documentation-rules.md`), contribution and template update rules
  (`docs/contributing.md`), and the seeded documentation map (`docs/README.md`).
- Short decision records: `docs/decisions/adr-template.md` and the generated index
  `docs/decisions/README.md` (`scripts/gen-decisions-index.sh`).
- Checks behind one entry point, `scripts/check.sh`: documentation (markdownlint-cli2, lychee),
  decision records (integrity, next number, index, merge readiness), template integrity
  (`.template/owned.sha256`), and project checks from `scripts/checks.d/`.
- Claude Code hooks (protect, Stop checks, project Stop hooks from `.claude/hooks/project/stop/`)
  and skills (`create-pr`, `update-template`, and `docs-review` as the `docs_review` module).
- CI workflows `docs` (with Node.js set up), `decisions`, and `docs-review`, with the runner chosen
  by a question and overridable by the repository variable `CI_RUNS_ON`.
