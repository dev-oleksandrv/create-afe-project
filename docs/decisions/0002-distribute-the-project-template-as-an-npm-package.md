# Distribute the project template as an npm package

## Context and Problem Statement

[ADR 0001](0001-distribute-the-project-template-with-copier.md) distributes the template with
Copier, which needs Python, uv or pipx, and `--trust`. Most projects already have Node.js, and the
checks already use `npx`. The ownership rules forbid local edits of template-owned files
(`template/docs/documentation-rules.md.jinja`, section 9), so an update does not need to merge
them. Which mechanism creates and updates projects with the fewest extra tools?

## Considered Options

* The npm package `create-afe-project`: a wizard with the questions of `copier.yml`, templates
  rendered by Nunjucks (Jinja syntax, so `template/` stays as it is), and an `update` command that
  replaces template-owned files, keeps the project block of `AGENTS.md` and seeded files, and runs
  migrations
* Keep Copier
* The npm package with a three-way merge of the old and new template versions

## Decision Outcome

Chosen option: "the npm package with an update that replaces template-owned files", because it
needs only Node.js, which the checks already need, renders the same files as Copier, and the
ownership check already makes a merge of template-owned files unnecessary. Versions are npm
versions with matching Git tags; the policy and the release are owned by
[`docs/maintaining.md`](../maintaining.md), sections 4 and 5.

Rejected: Copier (an extra Python toolchain for every user); a three-way merge (more code for a
case the ownership check forbids).

### Consequences

* Good, because creating and updating a project is one `npx` command, with no `--trust`.
* Good, because a project generated by Copier converts its answers file on its first update.
* Bad, because a local edit of a template-owned file is replaced, not merged; the update lists
  every such file, and the change shows in the pull request.
* Bad, because releases now also publish to npm, which needs the `NPM_TOKEN` secret.

### Confirmation

`scripts/checks.d/05-cli.sh` and `scripts/checks.d/10-template.sh` create and update projects
with the command line of the working tree on every pull request; the `release` workflow publishes
only tags with a changelog section and a matching `package.json` version.
